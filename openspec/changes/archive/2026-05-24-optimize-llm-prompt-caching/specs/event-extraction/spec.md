## ADDED Requirements

### Requirement: 智能体提示词静动边界重构与缓存优化
为了最大化大模型服务商（例如 DeepSeek、OpenAI）的 Prompt Caching 自动前缀缓存命中率，系统**必须且 SHALL** 遵循“静动分离”原则进行智能体提示词（Prompts）的重构与组装：
1. **提取阶段静动隔离**：系统在调用并行提取智能体（Extractor Agents）时，**必须且 SHALL** 保证其 `User` 消息中不包含任何静态动作说明、前缀引导文案或重复性业务规则，仅包含纯净的动态变量（即博文正文、原帖链接和发布时间）。原有的静态动作描述与业务指令**必须且 SHALL** 完全合并归入 `event_analysis.jinja2` 静态系统模板中，确保缓存前缀块与 `System` 消息（包含注入的 JSON Schema）在物理边界上完美对齐并形成稳健的长效缓存。
2. **裁决阶段静动隔离**：系统在调用终审裁判智能体（Judge Agent）时，**必须且 SHALL** 确保其 `User` 消息的尾部不附加任何静态合并指令或输出格式后缀。所有的裁决准则、模糊合并规则和数据规范**必须且 SHALL** 彻底收归于 `event_consensus_judge.jinja2` 静态系统模板中，使裁判智能体的 `User` 消息同样保持 100% 的纯动态内容状态，防止尾部无效静态文本造成 API Token 费用的持续性损耗。

#### Scenario: 提取器与终审裁判提示词完美实现静动隔离与缓存优化
- **WHEN** 触发增量分析提取任务且大模型调用被拦截改写时
- **THEN** 最终发往大模型（如 DeepSeek）的 `system` 消息包含了完整合并的静态核心指令与 Schema 说明，且 `user` 消息为纯动态的数据内容载体，无任何冗余静态前缀或尾缀拼接，完全对齐系统缓存块边界。
