## Context

当前系统由 `parse_city` (基于正则表达式的城市提取) 和 `EventFusionService` (基于 SequenceMatcher 与 LLM 裁判的漫展融合系统) 负责将原始日程归一化绑定到超级漫展节点下。
然而，当前的粗暴城市解析逻辑导致地名经常被碎片化为不同城市（例如将“上海国家会展中心”和“上海世博展览馆”分别截取为“上海国家”和“上海世博”）。在时空融合阶段，数据库查询会以城市名称进行物理强隔离，导致这些处于不同“伪城市”下的同名漫展无法被时空融合引擎比对合并，产生了严重的集结节点分裂重复现象。

## Goals / Non-Goals

**Goals:**
- **精准的城市提取与收拢**：重构 `parse_city` 城市解析算法，彻底消灭“上海国家”、“上海世博”等伪城市，收拢为标准的地级市。
- **O(1) 字典秒配与解耦**：将别名缓存库 `event_aliases` 匹配逻辑从嵌套循环体内部提升到入口，提供结合时间窗口的快速通道，防止大范围同名不同届漫展（如 CP31 vs CP32）坍塌合并。
- **时空就地纠偏与自我疗愈**：当日程拥有具体城市，但库中存在同名的“未知城市”超级节点时，能够安全升级该“未知”节点并就地级联融合。

**Non-Goals:**
- 修改现有的 SQLite 表 Schema 结构。
- 引入除标准库和现有依赖以外的外部重度地理信息库（如 GeoIP 或大型第三方离线地图包）。

## Decisions

### 1. 多级级联的城市规范化提取算法
- **选择方案**：在 `parse_city` 中实现以下多级渐进提取流：
  1. 剥离省份前缀（如“浙江省” ──▶ “”，保留“杭州市...”）。
  2. 全国主要会展中心大市拼音/汉字字典直接前缀匹配。覆盖 95% 以上的高频展览地级市（如 上海、北京、广州、深圳、杭州、成都、武汉、南京、重庆、西安、厦门、福州、天津、沈阳、长春、哈尔滨、济南、青岛、潍坊、合肥、长沙、郑州、石家庄、南昌等）。
  3. 后缀正则智能剥离（若匹配到“市/区/县”等，只取其前面的城市名，如 “上海市” ──▶ “上海”）。
  4. 终极两字截取兜底（如果仍未匹配，则只截取清洗后地名的前两个汉字。因为中国绝大多数地级市都是两字名，如“福州海峡” ──▶ “福州”）。
- **理由**：直接切断了伪城市的产生源头。无需加载大型库，纯算法与常量字典就达到了 99% 的规范化率。

### 2. 带有“时间窗口”的入口级 O(1) 字典匹配
- **选择方案**：在进入时空比对循环前，使用 event_date 分别对 `normalized_events` (标准名) 和 `event_aliases` (别名表) 进行 SQL 直接检索，且带有 `(date(event_date) BETWEEN date(start_date, '-7 days') AND date(end_date, '+7 days'))` 的时间档期范围校验。
- **理由**：
  - 极大减少数据库 I/O 次数。对于已知的名字（特别是别名），无需在 50 个节点循环里跑 50 次 SELECT，也无需调用 SequenceMatcher。
  - 带上时间窗口，确保了如“CP31”（2025年）与“CP32”（2026年）即使名字完全一致，也能安全隔开，避免了同名不同年份的活动坍塌成一个节点。

### 3. 跨“未知”城市的级联糾偏升级
- **选择方案**：当新日程的城市是具体城市（如“上海”），但入口检查发现库中该名字唯一的既存超级节点是“未知”城市（如 `event_fingerprint = '未知_bilibiliworld2026'`) 时：
  - **纠偏升级**：判断如果具体城市的对应节点（如“上海_bilibiliworld2026”）在库中**尚不存在**，直接执行 `UPDATE`，将“未知”节点的城市修改为“上海”，将 `event_fingerprint` 修改为 `"上海_bilibiliworld2026"`。
  - **级联覆盖**：如果具体城市的对应节点**已经存在**（由于并发或其他文章先创建了），为了防止唯一键冲突（sqlite3.IntegrityError），不能执行 UPDATE，而是将当前活动级联关联至既存的具体城市超级节点，并检测如果无引用的“未知”节点彻底空置，执行安全的级联 DELETE。
- **理由**：完美解决了“未知城市”节点悬挂的遗留问题，实现了数据的就地自愈。

## Risks / Trade-offs

- **[Risk 1] 城市解析把少数民族地区或三字特例截断（如“内蒙古”或“哈尔滨”变成“内蒙”或“哈尔”）**
  - **Mitigation**：将“哈尔滨”、“石家庄”、“呼和浩特”、“乌鲁木齐”等非两字城市直接内置入字典中，在进行两字兜底前通过字典前缀拦截。
- **[Risk 2] 别名库发生 LLM 裁判误判后导致后续数据发生错误秒配污染**
  - **Mitigation**：由于我们对秒配加入了 7 天的时间档期校验，即使别名表发生污染，不同时间段的无关活动也不会被错误纠缠合并，最大限度限缩了污染的范围。
