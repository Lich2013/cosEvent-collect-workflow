## Why

当前系统在提炼和展现 Cosplay 活动日程时，存在以下三个显著的设计局限，导致用户体验和数据消费精度不够完美：
1. **单人/跨平台日程冗余**：当 Coser 在同一个平台多次发布、或在不同平台（如微博、B站、小红书）交叉发布同一个参展活动日程时，系统会多次增量录入，在数据库中堆积大量的完全重复的活动日程。
2. **模糊名称对齐困难**：因为不同 Coser 对同一个大型展会（如 Bilibili World）的拼写和简称五花八门（如 "上海bw2026", "bilibiliword2026", "上海bw"），传统的相似度引擎受阻于过低的相似比率（<0.5）从而绕过 LLM 裁判直接独立建站，导致超级漫展节点严重碎片化。
3. **关键日期缺省**：部分 Coser 在发帖时默认粉丝知道日期，因而省略了具体日期（提炼为 "未知"），使得数据消费层（日历/排期看板）缺失关键排期脉络。但实际上，其他同去该展的 Coser 已经提炼出了明确的日期，系统需要智能借用并动态推演这些缺省的时间。

## What Changes

本变更聚焦于数据存储与展现层的极致硬化与去重合并，完全向后兼容，具体变更包括：
- **Coser 级别多源日程智能 Upsert 与描述融合**：在写入事务前，检索该 Coser 在全局平台的所有未来日程，对同城、同漫展 ID 的日程执行原位更新（In-place Merge），合并多平台发帖的日程描述，消除冗余。
- **缩写词典与自适应时空裁判扩容**：在清洗时前置对齐常见 ACG 缩写（如 "bw" ──▶ "bilibiliworld"）；同时，对于“同城同档期”但字面相似度低的特殊候选节点，将 LLM 裁判的触发范围扩容，并通过别名缓存物理旁路，实现低 Token 损耗下的高精对齐。
- **动态时间继承与视觉继承渲染**：在展现层（summary、calendar）与导出层引入“推算时间继承”。当日程日期为“未知”时，自动、实时继承其归一化超级节点的包络举办时间范围，并打上 `(推算自超级节点)` 的智能视觉标签。

### Modified Capabilities
- `event-centric-aggregation`: 扩展时空聚类引擎的缩写预对齐词典，扩容同城同档期的 LLM 别名裁判判定范围，并实现事务内 Coser 维度的跨平台/多发帖 In-place 智能去重合并。
- `event-calendar-view`: 控制台看板支持对 '未知' 日期的 Coser 日程实时继承并回显超级节点的推算时间。
- `data-export`: 数据导出服务支持在 calendar 和 default 视图中自动继承超级节点包络日期进行数据排版与对齐。

## Impact

- `src/services/db/event_repository.py`: 重构活动写入事务逻辑，实现跨平台/跨博文 Coser 级 In-place 智能去重合并与描述拼接。
- `src/services/fusion_service.py`: 升级相似度清洗策略（增加 ACG 缩写对齐词典），放宽同城同档期节点触发 LLM 裁判的置信度区间。
- `src/views/terminal_renderer.py`: 控制台日历与日程看板在渲染 "未知" 日期时自动继承超级节点包络时间。
- `src/services/export_service.py`: 导出日历与日程报表时自动继承超级节点包络时间。
