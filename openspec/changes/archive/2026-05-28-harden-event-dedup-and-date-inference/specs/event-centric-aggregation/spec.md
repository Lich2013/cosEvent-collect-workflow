## ADDED Requirements

### Requirement: Coser 维度跨平台与多发帖 In-place 智能去重合并
系统在执行日程原子写入事务（`save_extracted_events_transactional`）时，对于同一个 Coser 的日程，必须且 SHALL 实现全局未来日程的 In-place 智能去重合并。
1. **去重合并判断**：如果该 Coser 的既存未来活动记录（未取消）中，已存在指向**相同超级漫展 ID（`normalized_event_id`）且日期一致或相容（含 '未知' 日期）**的日程：
   - 系统 SHALL 判定为重复日程，禁止插入冗余新行。
2. **描述与来源融合**：
   - 系统 MUST 对重复日程执行 In-place 更新，保留更详细的日程描述或使用 ` | ` 拼接不同描述，并将 `raw_post_id`、`source_url` 和 `confidence` 更新为最新值，以实现多平台/多次发帖日程的最大化融合。

#### Scenario: 成功将微博与B站的重复 CP30 日程合并去重
- **WHEN** 数据库已录入 Coser A 微博发帖的 CP30 日程（日期 2026-05-02，描述 "第一天出黄泉"），新分析其B站发帖提炼出 CP30（日期 2026-05-02，描述 "在A15摊位"）并执行保存事务时
- **THEN** 系统未在 cosplay_events 插入新行，而是原位更新既有行，描述被智能融合为 "第一天出黄泉 | 在A15摊位"，退出状态码为 0

### Requirement: 缩写词典与时空同城同档期 LLM 裁判自适应介入
时空融合引擎必须支持常见 ACG 缩写清洗，并对同城同档期但字面相似度低的特殊候选节点进行裁判扩容。
1. **缩写词典对齐**：清洗漫展名称时，系统 SHALL 对 "bw" -> "bilibiliworld" 以及 "cp" -> "comicup" 进行简称替换，提升字面匹配相似度。
2. **同城同档期裁判扩容**：如果既存节点与新日程同城且档期在 $\le 3$ 天内重叠（或至少一方为 '未知'），即使字面相似度 Ratio 低于 $0.5$（低至 $0.2$），系统 SHALL 依然触发 LLM 裁判介入裁决，判定是否为同一实体。

#### Scenario: 同城同档期 BW 与 BilibiliWorld 被裁判成功融合
- **WHEN** 录入新日程 "上海bw2026"，与既存的 "bilibiliworld2026" 同城（上海）且日期完全一致，Difflib 得分低于 0.5 触发拦截时
- **THEN** 系统拉起 LLM 裁判并裁决判定二者为同一活动，将其归入相同超级节点，并将 "上海bw2026" 写入别名缓存表以供后续直接旁路，退出状态码为 0
