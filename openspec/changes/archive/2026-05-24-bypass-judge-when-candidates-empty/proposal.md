## Why

在当前的多模型共识仲裁机制（Consensus Mode）下，当并行提取器（Parallel Extractors）全部运行成功并完成候选列表的获取后，系统不论提取器返回的候选活动数量是否为空，依然会强行唤醒并调用金牌裁判大模型（Judge Agent）。

若所有并行提取器提取出的候选活动列表全部为空（即所有模型在第一阶段一致认定该博文中没有活动信息，`total_extracted_candidates == 0`），那么调用高推理裁判大模型是没有必要的，这平白耗费了极其昂贵的裁判大模型 Token 费用以及产生不必要的 API 请求网络开销与处理延迟。因此，需要增加自适应的裁判旁路逻辑（Judge Bypass），在候选草稿均为空时直接退出并返回空列表，完全避免无意义的终审判决开销。

## What Changes

- **裁判自适应智能旁路（Bypass Judge When Candidates Empty）**：在 `src/agents/event_agent.py` 的共识模式流程中，在过滤并收集到所有成功存活提取器的候选输出 `valid_outputs` 之后，统计所有提取器提取到的候选活动总数。若候选活动总数为 `0`（说明各存活模型达成了 100% “没有漫展活动”的完全一致共识），系统直接输出调试日志并旁路（跳过）终审裁判，安全、直接地返回空列表 `[]`。
- **与单侧降级和分歧仲裁解耦**：当至少有一方提取器提取到了非空活动时，说明模型之间存在分歧（Disagreement），系统依然会保持健壮的终审仲裁机制，继续唤醒高智商裁判智能体进行核验、去重与合并。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `event-extraction`: 升级多模型并行提取与裁判智能仲裁流水线。系统**必须且 SHALL** 智能分析存活提取器返回的候选数据：若所有存活模型回传的候选活动数量皆为 0，系统**必须且 SHALL** 自动旁路（跳过）终审裁判智能体（Judge Agent）的调用以完全节省 Token 费用，直接安全返回空列表。

## Impact

- `src/agents/event_agent.py`: 需要重构共识流程在提取器数据收集完成后的处理逻辑，加入对候选总数的自适应零值断言与旁路退出。
- `tests/test_cosevent.py`: 需增加对应的 Mock 单元测试，模拟多提取器均成功运行并返回空活动列表的场景，断言智能体立刻安全返回 `[]`，且断言终审裁判的 Runner 调用次数为 `0`（以彻底验证旁路成功）。
