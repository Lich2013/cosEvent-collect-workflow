## Context

当前 Cosplay 活动分析系统通过 Playwright 拦截微博的 `mymblog` Ajax 响应。当微博博文被编辑（`edit_count > 0`）时，为规避大模型相对日期推导时间轴倒流的问题，既往设计在爬行时直接使用“当前抓取时间”作为发布时间重锚。

然而，这导致陈年置顶（Pinned）微博或首次历史录入的编辑微博，其发布时间被错误地标记为最新抓取时刻。LLM 看到这种“伪最新发布”的时间锚点，会将 2025 年的历史绝对日期（如 9.20）判定为 2026 年未来的行程，造成大范围的历史行程被错误激活为未来行程。

我们需要重新规划时间对齐流程，建立一个物理精准、安全降级、动态识别的三层防御对齐系统。

## Goals / Non-Goals

**Goals:**
- 实现 100% 物理精准的微博最新编辑时刻抓取（通过查询 `editHistory` 接口并抓取 `statuses[0]["created_at"]`）。
- 保证高反爬环境下的极端健壮度：当 `editHistory` 接口因限流、失效或反爬被阻断时，能够静默降级为微博的原始 `created_at`，保持绝对年份上下文不失真。
- 保证实时编辑的灵敏度：在数据库服务层检测到实时的 edit 版本增加时，动态重置为当前抓取时间，防止相对时间（如“下周”）发生年份倒流。

**Non-Goals:**
- 对 B站、小红书等无显式 `editHistory` 接口的平台实现类似的底层历史查询（它们将保持目前的自适应内容对比合成版本与 `now_str` 重置逻辑）。
- 物理拉取和解析所有历史编辑版本的正文（系统仅关注最新编辑版的正文及时间戳，不需要对老版本正文进行 LLM 分析）。

## Decisions

### 1. 爬虫层采用 Ajax 异步轻量查询 `editHistory` 接口
- **选择**：使用 Playwright 共享的 `context.request.get(f"https://weibo.com/ajax/statuses/editHistory?mid={mid}&page=1")` 进行查询。
- **依据**：相较于重新打开一个新的 Page 页面或发起外部独立 HTTP 连接，使用 Playwright 的 Context APIRequestContext 共享了已经登录和校验通过的 Cookie（如 `SUB` 等），不仅执行开销在几毫秒级，且高度模拟真实浏览器用户点击行为，防反爬安全性极佳。

### 2. 爬虫层双重防御式降级（原始 `created_at` 兜底）
- **选择**：如果在爬行时 `editHistory` 接口抛出异常或无法返回 `statuses`，直接采用该微博的 original `created_at`，解析为北京时间字符串格式。
- **依据**：虽然 original `created_at` 与实际编辑日期可能存在几天的偏差，但它**绝对锁定了博文产生的物理年份上下文（如 2025 年）**。这确保大模型在推算 “9.20” 等绝对日期时依然指向 2025 年，彻底消除了将历史活动错误未来化唤醒的隐患。

### 3. 数据库服务层智能“有状态”判定
- **选择**：在 `DBService.save_raw_posts` 保存 Weibo 二次编辑版本时，通过 `SELECT` 查询 `base_post_id` 在库中是否存在任何先前版本记录：
  - 若**不存在**（场景 A：历史被动录入）：在 `INSERT` 插入该版本（如 `#v1`）记录时，保持 Scraper 传来的物理编辑发布时间/原始时间。
  - 若**已存在**（场景 B：实时主动编辑）：在 `INSERT` 插入该新二次编辑的 `#v` 后缀版本记录时，强行将该新记录的 `published_at` 重置重锚为 `now_str`（当前北京时间）。
- **依据**：在数据库层实现了“状态隔离与多版本追加”：完美解决了陈年老博文首次拉取时的时间漂移，又保证了监控周期内发生实时编辑时，新插入的编辑版本记录能以最新的今日为原点进行高精度解析，完美契合系统现有的级联软取消设计。

### 4. 智能体 Prompt 模板注入历史置顶微博 Few-Shot 坏例约束
- **选择**：在 `config/templates/event_analysis.jinja2` 和 `config/templates/event_consensus_judge.jinja2` 静态提示词模板中，专门设计并注入针对“陈年置顶微博历史编辑”的 Few-shot 反向坏例（Bad Case）指导，显式规制大模型的日期解析行为。
- **依据**：由于大模型天生倾向于将所有绝对日期（如 `9.20`、`10.6`）滑动到与“当前系统参考时间”（如 2026 年）相同的年份，在此处注入显式坏例，强行规约其必须以“博文发布时间”为基础年份还原为 2025 年行程，并在系统参考时间下判定为过期进行过滤，从语义感知层筑起终极防线。

## Risks / Trade-offs

- **[Risk]**：微博 `editHistory` 接口由于调用频繁被限流或返回 403。
  - **[Mitigation]**：只在 `edit_count > 0` 时触发此接口（平均每位 Coser 仅有 10% 左右的微博是 edited 的，调用频率极低）。同时，爬虫层通过严密的 `try...except` 拦截异常并静默执行原始 `created_at` 年份锁定降级，保证系统绝对不会崩溃。
- **[Risk]**：襄阳华侨城奇幻谷等特殊的绝对日期描述在 LLM 中仍旧被年份滑动影响。
  - **[Mitigation]**：高精度的 `published_at` 作为环境参数传入大模型提示词静动模板，大模型能极其稳定地根据该基准和当前系统时间判定行程过期。
